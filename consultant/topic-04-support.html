01 · Client evidence

What Dune & Pearl has actually told you

Known facts for Topic 04

  • The camp uses check-in kiosks, booking laptops and an environmental sensor controller.
  • Temporary reception staff find the booking interface crowded.
  • IT wants to update the booking laptops.
  • An older receipt printer may not have a compatible driver.
  • Reception staff need to find and confirm bookings after short training.
  • IT needs to apply approved settings consistently to 20 laptops.
  • The sensor controller must respond within its designed control time.

Consultant rule

Separate evidence from assumption. “The booking screen is slow” does not prove that the operating system is the cause. “A new OS will fix it” is a proposal that still needs evidence.

02 · Quick knowledge

Use the right idea for the right problem

Memory management

Allocates and manages RAM so processes can work effectively.

Multitasking

Schedules work between processes rather than running one task only.

Device drivers

Allow the operating system to communicate with hardware such as the receipt printer.

Networking services

Support communication between devices and network resources.

Security services

Support accounts, permissions and protections.

Performance

Also depends on workload, processor, RAM, storage, network, background tasks and the application.

OS characteristics

Embedded

Built into a dedicated device or system. This describes purpose and device type.

Real-time

Designed to respond within defined timing constraints. This describes timing behaviour.

Multi-user

Supports multiple users with separate sessions, accounts or permissions.

Remember

A system can have more than one characteristic. A dedicated controller can be both embedded and real-time.

Interface chooser

GUI

Useful when: visual controls and familiar workflows help the user.

Check: clutter, resource use and accessibility.

CLI

Useful when: precise administration, scripting or automation matters.

Check: knowledge required and impact of mistakes.

Menu-based

Useful when: a user needs a restricted set of repeated choices.

Check: flexibility, navigation and alternative routes.

Adapted interface

Useful when: access needs require screen reading, magnification, voice, switches or other support.

Check: with the actual user and complete workflow.

03 · Task support

Use these prompts when you get stuck

T04-KC

Embedded vs real-time

Do not give two vague definitions. Identify the property each term describes, then use one system that could have both properties.

Planning prompt

Ask: is this describing what the device is for, or how quickly it must respond?

T04-A1

Match technology to the user or system

Start with user/system → task → need → suitable interface or OS characteristic → reason.

Quality check

Could another interface also work? If yes, explain why yours fits the evidence better.

T04-A2

Sketch the check-in screen

Your design needs booking search, identity confirmation, status and a help route. Annotate how the design prevents errors and supports access.

Design questions

What happens if a search fails? Can the user recover? Is the next action obvious? Is there an accessible alternative to the normal route?

T04-A3

Plan the OS upgrade test

Cover the printer, booking application, security settings and rollback. A strong test has an expected result, evidence, a pass/fail condition and a response if it fails.

Consultant test

“The application opened” is weak evidence. Test the actual check-in workflow and the failure route.

T04-ER

Extended response

Explain OS services, analyse two interface choices, then justify a preferred check-in design using the Dune & Pearl evidence.

Reasoning frame

Claim → case evidence → consequence for a stakeholder → limitation → supported decision.

T04-TR

Transfer to another organisation

Do not just change the company name. Explain how the user and task change which interface is suitable.

T04-REVIEW

Improve after feedback

Keep the original draft. Make the improvement visible and explain what changed, why it is stronger and what you still need to improve.

04 · Quality check

Move from description to consultant reasoning

DescribeWhat is it or what happens?
ExplainWhy or how does it matter?
AnalyseWhat consequence follows for users or the organisation?
JustifyWhy is this choice stronger than a realistic alternative?
Common traps
  • Calling an application an operating system.
  • Assuming a slow system needs a new OS.
  • Treating embedded and real-time as synonyms.
  • Assuming a GUI is best for every user.
  • Calling a kiosk accessible simply because it has fewer choices.
  • Rolling out an upgrade before checking drivers, applications, security settings and rollback.

Before you submit any Topic 04 work

Can you point to the Dune & Pearl evidence that supports your choice? Have you explained a consequence rather than listing a feature? Have you acknowledged a limitation? Have you labelled anything that still needs client confirmation?
