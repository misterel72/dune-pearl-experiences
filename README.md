# Dune & Pearl Experiences

A fictional Qatari leisure and tourism organisation used as the central vocational case study for Pearson BTEC International Level 3 Information Technology.

## Live site

https://dune-pearl-experiences.netlify.app/

## Purpose

The site gives students a consistent organisation through which to explore IT infrastructure, stakeholders, data, connectivity, security, organisational policy and IT management.

## Deployment

The project is a static website designed for continuous deployment through Netlify.

## Assessment boundary

This public repository contains only student-facing fictional company information and formative task routes. Protected Pearson assignments, teacher answers, answer-rich speaker notes, student work and assessment records must not be added here.

Expandable support is native HTML.

### Ownership of learning content

- Classroom remains the starting point for lesson materials, dates, quizzes and feedback.
- The teacher slides introduce and model the learning.
- The website provides fictional client evidence and a route to the corresponding tasks.
- The personal workbook retains answers, first drafts, revisions and reflections. The site does not collect or save answers.
- Classroom links deliberately open the class list because a verified school course URL has not been supplied. Never guess a class URL or publish personal workbook links.

### Source and consistency

Aligned with `BTEC_L3_U1_Student_Workbook_Dune_Pearl_v1.1.docx` and the seven standalone teacher decks L01–L07. Lesson and task codes are primary references; page numbers can change in student copies.

L02's practice brief and L05's organisation brief / three observations reproduce their workbook source wording. L07 retains the unfamiliar charity scenario, rather than converting every activity into Dune & Pearl. Do not invent missing budgets, queue timings or offline procedures, or import later scenario figures into these early lessons. Role-play answers must be labelled simulated, not reported company facts.

The homepage distinguishes existing digital services from incomplete integration, manual processes and the board's improvement goal. Its information-flow diagram is conceptual, not a verified architecture.

### Extending the site

Use the existing `consultant/hub.css` and lesson-page structure. Match new pages to approved workbook tasks and completed decks. Add only available lesson links to both the hub and lesson navigation. Check relative links, section anchors, mobile CSS and keyboard access before publishing. Do not publish the teacher PPTX files as student resources without preparing an appropriate student-facing version.
